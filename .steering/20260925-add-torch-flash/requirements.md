# 要求内容

## 概要

参加画面に「フラッシュも使う」オプションを追加し、スマホのカメラ用ライト(トーチ)を画面点滅と同じタイミングで点灯・消灯させる(PRD 機能6、P1)。

## 背景

- フラッシュでの点滅は本サービスで最も大事にしたい機能(PRD「本命」)。画面点滅(MVP)で同期の仕組みができたので、その上に載せる
- 画面より強い光で、暗い会場でも遠くまで届くようにしたい
- カメラの許可が必要なため、使うかどうかは参加者が選べるようにする(標準の画面点滅は許可不要のまま)
- iPhone(Safari)でトーチが使えるかは未確認(PRD 未決定事項5)。開発者の手元にあるのはiPhoneのみ(Android端末なし)のため、iPhoneで実際に光るかを最初に確かめられる形で作る

## 実装対象の機能

### 1. 「フラッシュも使う」オプション
- 参加前の画面に、オン/オフを切り替えるボタンを表示する(既定はオフ)
- ボタンの近くにカメラの許可が必要な理由と「撮影・録画はしません」を表示する
- オンにしたときに初めてカメラの許可を求める
- 点滅中もメニューからフラッシュのオン/オフを切り替えられる

### 2. フラッシュの点滅
- 画面点滅と同じ Player の判定(同じ時刻計算)で、トーチを点灯・消灯する
- 取得したカメラ映像は表示・保存・送信しない
- QRコード表示中・一時停止中・タブ切替中は消灯し、点滅の再開とともに再び光らせる

### 3. 対応していない場合・許可されなかった場合の扱い
- ブラウザがトーチの制御に対応していなければ、ボタンを無効にして「この端末ではフラッシュを使えません」と表示する
- カメラを取得してもトーチを持たない場合も同じ表示にする
- カメラの許可を拒否された場合は案内を出し、画面点滅は続ける

### 4. 1拍が短いときの案内
- フラッシュを使うとき、1拍が300ms未満なら「フラッシュは切り替えが遅れることがあるため、1拍300ms以上をおすすめします」と表示する

## 受け入れ条件

### 「フラッシュも使う」オプション
- [ ] 参加前の画面に「フラッシュも使う」ボタンが表示され、初期状態はオフ
- [ ] ボタンの近くに「フラッシュを使うためにカメラの許可が必要です。撮影・録画はしません」と表示される
- [ ] ページを開いただけ・「タップして参加」を押しただけではカメラの許可を求めない
- [ ] ボタンをオンにしたときにカメラの許可を求める
- [ ] 点滅中のメニューに「フラッシュを使う / フラッシュを止める」があり、切り替えられる

### フラッシュの点滅
- [ ] 許可後、トーチが画面点滅と同じタイミングで点灯・消灯する(iPhone実機で目視確認。iPhoneが非対応の場合は「使えません」表示になることを確認)
- [ ] 画面に映像が表示されない(`<video>` `<canvas>` を使わない)
- [ ] 通信が発生しない(カメラ映像を送信しない)
- [ ] QRコード表示・一時停止・タブ切替でトーチが消え、再開するとまた光る
- [ ] フラッシュをオフにしたとき・参加画面を離れたときにカメラを解放する(`track.stop()`)

### 対応していない場合・許可されなかった場合
- [ ] トーチ非対応のブラウザ(PCのブラウザなど)で、ボタンが無効になり「この端末ではフラッシュを使えません」と表示される
- [ ] カメラの許可を拒否すると「カメラが許可されなかったため、フラッシュは使えません」と表示され、画面点滅は続く

### 1拍が短いときの案内
- [ ] 1拍が300ms未満の設定でフラッシュをオンにすると、おすすめの案内が表示される
- [ ] 1拍が300ms以上なら案内は表示されない

## 成功指標

- iPhone(Safari)でトーチが対応しているかどうかが確定する(PRD 未決定事項5の解消)
- 対応している場合、フラッシュが画面点滅から最大150ms以内で追従する(PRD セカンダリーKPI。スロー動画で測定)

## スコープ外

以下はこのフェーズでは実装しません:

- 画面は消灯したままフラッシュだけを光らせるモード(PRDにない)
- トーチの切替遅延を見越して早めに点灯させる補正(実機で遅延を測ってから検討する)
- Android実機での確認(開発者の手元に端末がないため、確認は後日)
- オフライン対応(PWA)・和文モールス(別のP1機能)
