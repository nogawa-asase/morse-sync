# モールスシンク - アイデアメモ

## このドキュメントの位置づけ

このドキュメントは壁打ち・ブレストの成果物で、正式な仕様書ではありません。

## プロダクトビジョン

複数人のスマホで、同じモールス信号をほぼ同時に、カメラのフラッシュのライトや画面で光らせるWebサービス。主催者が作った点滅パターンをQRコードで配り、参加者は読み取ってタップするだけで、全員のスマホが揃って点滅する。

本命はカメラのフラッシュのライトでの点滅。ただし画面点滅のほうが容易に作れ、どの端末でも確実に動くため、まず画面点滅で同期の仕組みを完成させ、その上にフラッシュを載せる順番で進める。

**一言で言うと**: QRコードを読むだけで、みんなのスマホが揃ってモールス信号を光らせる

---

## 解決したい課題

### 今困っていること

1. **複数台で光を揃えるのが難しい**
   - 各自が手動で「せーの」で始めても、すぐにバラバラになる
   - 端末同士を通信でつなぐ仕組みは準備が大変

2. **参加してもらうまでのハードルが高い**
   - アプリだとインストールが必要で、その場に居合わせた人には頼みにくい
   - iPhoneとAndroidが混在すると手順が揃わない

3. **点滅パターンを全員に正しく伝えるのが面倒**
   - メッセージ内容、開始タイミング、速さ、色を口頭で伝えて設定してもらうのは現実的でない

4. **モールス符号への変換やタイミングの計算が面倒**
   - 文字→符号の変換、短点・長点・間隔の長さを人が計算するのは手間

## ターゲットユーザー(仮)

### ペルソナ1: 主催者

- **経験**: スマホの操作は普通にできる。モールス信号に詳しくなくてもよい
- **やりたいこと**:
  - メッセージを入力して、点滅パターンを簡単に作りたい
  - 作ったパターンをその場で参加者に配りたい

### ペルソナ2: 参加者

- **経験**: QRコードの読み取りができる程度
- **欲しいもの**:
  - インストールや登録なしで参加できる
  - 読み取ってタップするだけで始まる
  - カメラなど、よくわからない許可を求められない

## 主要機能の候補

### P0 (MVPで絶対必要)

#### 1. 点滅パターンの設定
- 設定項目は4つ
  - メッセージ内容(英数字)
  - 時計に合わせるタイミング(同期の周期)
  - 点滅の1拍の時間(デフォルト250ms)
  - 画面を光らせるときの色
- 入力内容から所要時間を計算して表示
- 所要時間が同期の周期を超える場合は警告
- 対応外の文字(日本語など)は「この文字は送れません」と表示し、QRを作る前に気づけるようにする

#### 2. QRコードでの設定共有
- 設定をすべてURLに入れ、そのURLをQRコードにして表示
- QRコードはブラウザ内で生成(サーバー不要)
- 主催者の画面に出したQRを、参加者が自分のカメラで読み取る
- 同じURLをLINEなどで送れる「共有」ボタンも用意

```
https://nogawa-asase.github.io/morse-sync/#v=1&l=en&m=HELLO&p=30&u=250&c=ffcc00
# 開くと同じ設定のページが表示される
```

#### 3. 時刻同期による画面点滅
- 画面全体を点灯色と黒で切り替えて点滅
- 各端末が「現在時刻が同期の周期で割り切れる時刻」を開始点として計算し、毎周期メッセージを開始する(例: 周期30秒なら毎分0秒・30秒)
- サーバーや端末同士の通信は使わない

#### 4. 参加開始の操作
- ページを開いたら「タップして参加」を1回押してもらう
- このタップをきっかけに、スリープ防止とフルスクリーン化を有効にする
- 最大輝度にしてもらうよう画面上で案内する(ブラウザからは輝度を変えられないため)

### P1 (重要だけど後回しでもいい)

#### 5. フラッシュ(トーチ)での点滅 【本命】
- このサービスで最も大事にしたい機能。P1にしているのは実装の順番の都合で、重要度が低いわけではない
- 画面点滅(P0)で作った同期の仕組みを、そのままフラッシュの点灯/消灯に使う
- 参加者側ではオプションボタンにする(カメラの許可を嫌がる人もいるため、使うかどうかを選べるようにする)
- カメラの許可が必要なので、ボタンの近くに「フラッシュを使うためにカメラの許可が必要です。撮影・録画はしません」と表示
- 対応していない端末ではボタンを出さない、または無効表示

#### 6. オフライン対応(PWA)
- 一度アクセスしたらページを端末に保存し、次回からは電波がなくても開けるようにする
- 設定入りのQRコードは、保存済みのページならオフラインでも読み込める
- 想定する流れ: 事前にネットがある場所で一度開いてもらう → 当日はQRコードを読むだけ

#### 7. 和文モールス対応
- `l=ja` で和文モードに切り替え
- 濁点・半濁点は別の符号として送る(「カ」+濁点)
- 漢字は送れないので、ひらがな・カタカナで入力してもらう
- 和文と欧文が混在する場合の切り替え符号の扱いは、対応時に決める

### P2 (あったら嬉しい)

#### 8. 音での出力
- 個人の練習用として、オン/オフ切り替えで追加
- 複数台での同時使用には向かない(後述)ため、既定はオフ

#### 9. ワンダーリボンライト連動
- サンリオピューロランドのワンダーリボンライトを、スマホから出す高周波音で点滅・色変えさせ、モールス信号に合わせて光らせる
- ブラウザでの画面点滅がうまくいった後に検討する
- 詳細は「技術的な検討事項」を参照

#### 10. ネイティブアプリ版
- ブラウザ版で手応えがあれば、Expoでアプリ化を検討
- アプリならではの利点: 画面輝度を最大にできる、トーチを確実に制御できる、端末同士の近距離通信で設定を共有できる

### 既存の方法との比較

|------|-------------|---------------|-------------------|------------|
| インストール不要 | ✅ | ❌ | ✅ | ✅ |
| iPhone/Android共通の手順 | ✅ | △ | ✅ | ✅ |
| 複数台で揃う | ✅ | ✅ | ❌ | ❌ |
| 設定をまとめて配れる | ✅ | ✅ | ❌ | ❌ |
| 許可なしで使える | ✅ | ✅ | ✅ | ✅ |
| 光の明るさ | 🚧 | ✅✅ | - | - |

### このサービスの強み

1. **QRコードを読むだけ**
   - インストールも登録も不要
   - 設定内容はURLに入っているので、配る側も受け取る側も迷わない

2. **サーバーなしで揃う**
   - 各端末の時計を基準にするので、端末同士の通信が不要
   - 何人参加しても仕組みは同じ

3. **許可を求めない**
   - 標準の画面点滅はカメラなどの許可が一切いらない
   - フラッシュは使いたい人だけが納得して許可する

4. **シンプル**
   - 静的なページだけで完結し、GitHub Pagesに置くだけで公開できる

## 技術的な検討事項

### ブラウザ版かアプリ版か

**候補1: ブラウザ版**
- QR → ページが開く → タップで開始。数秒で参加できる
- GitHub Pagesに置くだけで、iPhoneもAndroidも同じURLで参加できる
- 修正はファイルを更新すればすぐ全員に反映
- 画面輝度は操作できない、iPhoneでのトーチは不確か

**候補2: ネイティブアプリ版(Expo)**
- QR → App Store → インストール → 各種許可 → 開始。初回のハードルが高い
- 配布にはApple Developer Program(年会費)と審査、またはTestFlightが必要。Androidは別途手続き
- 画面輝度の最大化、トーチの確実な制御、オフライン動作が可能

**結論**: まずブラウザ版で「複数台が同期して光る」仕組みを検証する

### 画面点滅

- 背景色の切り替えなので、どの機種・ブラウザでも動く
- スリープ防止: Wake Lock APIを使う(iOSのSafariでも使える)
  - ユーザー操作をきっかけに有効化する
  - タブ切り替えや画面を閉じると解除されるので、ページに戻ったときに再取得する
- ユーザーが電源ボタンで画面を消したり、別アプリに切り替えたりすると止まる(アプリでも同じ)

### フラッシュ(トーチ)

- カメラ映像を取得し、そのトラックにtorchをオンにする設定を与える方式
- AndroidのChromeは対応
- iOSのSafariは長く非対応とされてきたが、WebKitに対応の変更が入っている。どのiOSから使えるかは未確認 → 実機で要検証
- iPhoneの他のブラウザも中身はWebKitなので、Safariと同じ扱い
- HTTPSのサイトである必要がある(GitHub Pagesは満たす)
- オン/オフ切り替えに遅延があるため、画面点滅より遅めの速度で運用する前提

### 時刻同期

- 開始時刻の計算: 現在時刻を同期の周期で割り切れる時刻の次を開始点にする
- スマホの時計は通常ネットワークで自動補正されているので、端末間のズレはおおむね小さい
- 点滅のタイミングは「前の点滅から○ミリ秒後」と積み重ねず、「開始時刻から何ミリ秒目にオン/オフするか」を毎フレーム現在時刻と照らし合わせて決める(誤差が蓄積しない)
- 1拍は200ms以上を推奨(画面の更新間隔や端末の時計の微差を吸収するため)

### モールスのタイミング

- 比率はITU-R M.1677(国際電気通信連合の勧告)に準拠: 短点を1単位として、長点3単位、符号内の間隔1単位、文字間3単位、単語間7単位
- 1拍の絶対的な長さ(速さ)は国際標準では決まっておらず、用途に合わせて任意に決める
- 速さの目安にはWPM(1分間に送れる単語数)を使う。基準の単語「PARIS」が単語間の空白込みで50単位なので、1単位のミリ秒は「1200 ÷ WPM」
- デフォルトは1拍250ms(約4.8WPM)。無線の初心者向けくらいのゆっくりした速さで、目で読み取る光信号に向く

### URLパラメータ(仕様バージョン1)

| キー | 内容 | 例 |
|-----|------|-----|
| v | 仕様バージョン。後から項目を追加・変更しても古いQRを正しく読むため | `1` |
| l | 文字の種類。省略時は欧文 | `en`(将来 `ja`) |
| m | メッセージ(エンコードして格納) | `HELLO` |
| p | 同期の周期(秒) | `30` |
| u | 1拍の長さ(ミリ秒)。省略時は250 | `250` |
| c | 点灯時の色(16進数) | `ffcc00` |

- 設定は「?」ではなく「#」の後ろに入れる(再読み込みなしで設定を書き換えられる)
- キーは1文字にしてURLを短く保つ(QRコードの模様が粗くなり、画面表示からでも離れた位置から読み取りやすい)

### 変換表

- 「A→・−」のような対応表をデータとしてプログラム本体から分けて持つ
- 変換処理は表を引くだけにして、和文対応は表を追加するだけで済むようにする

### 音を使わない理由

- 光は数十ミリ秒ずれてもほぼ同時に見えるが、音は同じズレでも二重に聞こえやすい
- 端末ごとに音が出るまでの遅延が違い、Bluetoothイヤホン接続時はさらに大きくずれる
- 大人数で同時に光らせる演出では、画面の色を切り替える方式が一般的

### ワンダーリボンライト連動

- 前モデルのライトは、パレード楽曲に含まれる高周波音(20kHz前後)で制御されていたとされ、個人の解析をもとにWeb Audio APIでブラウザから光らせる実例がある(125msごとに周波数を切り替えて一連の周波数を出す方式)
- ワンダーリボンライトは既存ショーでも動くという報告があり、同じ方式を引き継いでいる可能性がある(未確認)
- 調べ方: まず前モデル用の公開プログラムで反応するか試す → パレード音源を20kHz付近まで録れるマイクで録音し、スペクトログラムで周波数の並びと色の対応を解析
- 利点: 1台のスピーカーから音を出すだけで届く範囲のライトが同時に光るので、時刻同期が不要になる
- ライト同士の赤外線通信はiPhoneでは真似できない
- 1命令に数百ミリ秒かかると見込まれ、さらにゆっくりしたモールスになる
- 即座に点灯/消灯できる命令があるのか、決まったパターンを呼び出す方式なのかは要解析

### 技術構成

- HTML / CSS / JavaScript のみ(ビルドツールなし)
- QRコード生成はブラウザ内のJavaScriptライブラリ
- 公開先: GitHub Pages
- リポジトリ名: `morse-sync`

## 非機能要件(とりあえず)

### パフォーマンス
- ページはなるべく軽くする(イベント会場で大勢が一斉に読み込むと、携帯回線が混雑するため)
- GitHub Pagesの帯域は月100GBのソフトリミット。1時間1000アクセス程度なら十分余裕がある
- 一度読み込めば、点滅中の通信はゼロ

### 使いやすさ
- QRを読んでタップするだけで参加できる
- 標準の機能では許可を求めない
- スマホでもPCでも使える

### 信頼性
- 端末が増えても、同期の仕組みは変わらない
- スリープ防止が解除されても、ページに戻れば復帰する

### 安全への配慮
- 強い点滅は光に敏感な人に負担になることがあるので、大人数で使う場合は点滅速度を抑えめにする
- 高周波音(ワンダーリボンライト連動)は子どもや若い人、ペットに聞こえることがあるので音量は控えめに
- 高周波音での制御はパークの外で楽しむ前提(パーク内では周囲のゲストのライトやパレード演出に干渉する)

### 拡張性
- 仕様バージョン(v)と文字の種類(l)を最初から持つ
- 変換表をデータとして分離しておく

## 成功指標(とりあえず)

### ユーザー視点
- **参加しやすいか**: QRを読んでから点滅が始まるまで、説明なしで進める
- **揃って見えるか**: 複数台を並べたとき、ほぼ同時に点滅しているように見える

### プロダクト視点
- **動作環境**: iPhone / Androidの主要ブラウザで画面点滅が動く
- **フラッシュ**: 対応端末で、フラッシュが画面点滅と揃って点滅する
- **同期精度**: 数台で試して、点滅のズレが目で気にならない

## 今後の検討事項

### まだ決めてないこと

1. **消灯時の色**
   - 黒に固定するか、パラメータで指定できるようにするか

2. **和文と欧文の混在**
   - 切り替え符号をどう扱うか

3. **受信(タップ→テキスト)機能を入れるか**
   - 画面を長押し・短押しして打鍵し、文字に解読する機能
   - 短点と長点のしきい値を固定にするか、打鍵速度に合わせて自動調整するか

4. **学習モードを入れるか**
   - ランダムな文字を鳴らして当てるクイズ形式など

### 技術的に不安なこと

1. **iPhoneのブラウザでトーチが使えるか**
   - 実機で確認が必要

2. **実際の同期精度**
   - 端末の時計のズレ、画面の更新タイミングで、どの程度揃うか

3. **ワンダーリボンライトの制御方式**
   - 前モデルと同じ方式か、どんな命令があるか

### 検討したが採用しないこと

- **ソースコードごとQRコードにして配布**: QRの容量(最大3KB弱)が足りない、data:形式のURLは最近のブラウザで開けない、HTTPSでないとスリープ防止などが使えないため不採用
- **Bluetooth・AirDropでのプログラム受け渡し**: iPhoneのSafariはWeb Bluetooth非対応、AirDropで受け取ったHTMLはWebページとして動かしにくいため不採用。オフライン対応はPWAで行う
